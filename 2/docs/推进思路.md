我觉得现在**可以选一个研究几何角度了**，但要注意：选的是**问题解释和停止风险诊断角度**，不是最终方法角度。

现在最稳的选择是：

> **source-route exposure localization：源路径搜索暴露局部化。**

也就是：

> 多 Agent 不是简单“答案相似”才出问题，而是它们的搜索努力集中在少数 source-route strata 上；因此 no-new-item stop 只能说明这些局部区域被耗尽，不能说明全局目标集合已经完成。

这个角度现在可以作为论文核心假设继续推进。
但 `low-exposure challenger` 暂时还不能作为主方法贡献，因为你这次真实盲测里它找回了 2 个真遗漏项，但没有超过 random challenger 平均水平。报告里 homogeneous 条件 `exposure_gini=0.7708`、召回 `17/24=70.8%`，属于 false stop；route_partitioned 条件 `exposure_gini=0.3854`、召回 `24/24=100%`；low-exposure challenger 从 homogeneous 后补回 2 个真遗漏项，但 random challenger 20 次平均也有 2.15 个。这个结果非常诚实，也非常有价值。

## 一、现在要不要“定方向”？

要定，但只定到这个程度：

```text
主研究角度：
source-route exposure localization as a stopping-risk diagnostic

暂不定：
low-exposure challenger as final method
```

也就是说，现在论文主线可以从：

> 我们提出一个几何方法解决 false completion。

改成：

> 我们发现并验证一种覆盖过程中的局部化失败规律：当搜索暴露集中在少数 source-route strata 时，no-new-item stopping 更可能只是局部耗尽，而不是全局完成。

这就足够正，而且不冒进。

## 二、为什么现在选 exposure localization，而不是别的几何角度？

因为它同时满足四个条件。

### 1. 它不是已有 embedding collapse 的重复

已有工作已经做了 reasoning trace embedding、cosine similarity、effective rank、多 Agent diversity。你们如果继续走“Agent 输出 embedding 几何”会撞车。

但 exposure localization 看的是：

```text
Agent 实际在哪些 source-route strata 上搜索过
```

不是看：

```text
Agent 说出来的答案语义相不相似
```

这个差异很关键。

### 2. 它直接服务于 safe stopping

`exposure_gini` 不是为了证明 Agent 多样性，而是为了判断：

> 当前 no-new-item 是否有资格作为停止证据？

理论计划里已经把它表述得很清楚：当搜索暴露集中在少数 strata 时，no-new-item stop 只能证明局部耗尽，而不能证明全局完成；并且现在暂时不宣称 phase transition，只尝试建立 residual missing mass 与 exposure localization 的关系。

### 3. 它已经有真实盲测信号

你这次盲测最关键的对比很漂亮：

| 条件                | exposure Gini | Recall | 结论              |
| ----------------- | ------------: | -----: | --------------- |
| homogeneous       |        0.7708 |  70.8% | false stop      |
| route_partitioned |        0.3854 |   100% | safe / complete |

这不是模拟了，是 runtime-blind policy-clause discovery。Agent 不知道 oracle，oracle 只用于评分。这个结果已经足够支持继续推进这个角度。

### 4. 它比原来的 DICE-Lite 更像“理论先行”

原来的 DICE-Lite 是：

```text
分区搜索 + ledger + challenger + risk score
```

现在变成：

```text
发现 failure law
→ exposure localization
→ local exhaustion
→ stopping-risk diagnostic
→ 再决定怎么 challenger
```

这个顺序更像师兄那篇：先找控制量，再让方法自然长出来。

## 三、现在不能选什么？

### 1. 不能选 “low-exposure challenger 方法” 作为核心

现在证据不够。

因为 low-exposure challenger 虽然找到了 2 个遗漏项，但 random challenger 平均是 2.15，最高能找到 5 个。报告自己也写得很清楚：当前证据更支持 exposure localization 作为 stopping-risk diagnostic，而不是支持这个 bottom-k challenger 规则已经是最终干预方法。

这不是坏消息。恰恰说明你们没有自欺欺人。

现在应该写：

> low-exposure challenger confirms that low-exposure strata may contain residual missing mass, but the current bottom-k selection rule is not yet superior to random challenge.

不要写：

> low-exposure challenger outperforms random.

### 2. 不能选 “Gini 比所有变量都强” 作为核心

模拟里 `exposure_gini` 和 `discovery_gini` 几乎打平，真实盲测里二者也都很高。理论计划里也承认，`exposure_gini` 的价值更多是机制解释：它记录了系统在哪里搜索过，即使什么也没发现。

所以现在主张应该是：

> exposure localization 是机制核心；discovery localization 是伴随诊断。

不是：

> exposure Gini 全面碾压 discovery Gini。

# 下一步优先级

## 第 1 优先级：再跑一个真实代码仓库盲测

选一个 bounded code repository discovery task。

要求：

* Agent 运行时不知道 oracle 总数；
* 有明确 source-route strata；
* 有 homogeneous、route_partitioned 两个条件；
* 能判断 false stop；
* 能记录 exposure distribution。

最少条件：

```text
homogeneous
route_partitioned
homogeneous + random challenger
homogeneous + low-exposure challenger
```

最少指标：

```text
exposure_gini
discovery_gini
source_route_coverage_ratio
recall
false_stop_at_90
false_stop_at_95
challenger_new_true_items
```

如果代码任务也出现：

```text
homogeneous 高 exposure_gini + false stop
route_partitioned 低 exposure_gini + 高 recall
```

那这个角度就很稳了。

---

## 第 2 优先级：做多 seed / 多任务稳定性

现在 policy 任务里 homogeneous 和 route_partitioned 各只有一个主要条件结果，challenger 里 random 有 20 个 seeds，但 low-exposure 只有 1 个 seed。这个会被审稿人追问。

下一轮至少要有：

```text
每个任务 5 个 seeds
每个 challenger 至少 10 个 seeds
至少 2 个任务类型
```

不一定需要很大，但要能回答：

> 这个规律是否稳定，而不是某个 seed 刚好如此？

---

## 第 3 优先级：改进 challenger，但不要现在把它当主贡献

当前 bottom-k low-exposure 规则太粗了。它的问题是：

> 低曝光区域不一定有高产出。

所以 random 有时会更好，因为 random 可能碰巧选到低曝光且高目标密度的区域。

下一版 challenger 应该从：

```text
低曝光
```

升级为：

```text
低曝光 × 高潜在产出
```

可以先用一个简单 runtime score：

```text
priority(s)
=
under_exposure(s)
× potential(s)
```

其中：

```text
under_exposure(s) = 1 - normalized_exposure(s)
```

`potential(s)` 不能用 oracle，可以用运行时可见代理：

* stratum 的文档长度 / 文件数；
* query 与 stratum 名称或内容的语义相关度；
* 该 stratum 所属 source family 在相邻 routes 中的历史 discovery rate；
* 是否属于 boundary route、exception route、deadline route 等高风险类型；
* 是否与已有遗漏类型相似，但尚未被充分搜索。

这个可以叫：

> **Low-Exposure High-Potential Challenger**

或者更简洁：

> **Residual Potential Challenger**

但现在还不用写进论文标题。
