# 论文实验完善计划

目标：不改方法主线，只补强证据可信度，让实验更像“证书失配 + evidence-condition controller”的系统验证，而不是少数任务上的脚本化现象。

## 已有基础

当前实验已经能支撑三条核心判断：

1. homogeneous route reuse 会制造 localized evidence。
2. localized evidence 如果被当成 global stop，会造成 false certification。
3. broader source-route exposure 提高 eligibility，但 broad exposure 不等于 SAFE。

因此，后续补实验只围绕“可信度补强”展开，不新增复杂方法名，不把 `residual-potential` 写成最优搜索方法。

## 优先级

### P0. controller decision table

目的：直接回应“是不是永远不 stop / 只是保守”的质疑。

要补的表：

- `Task`
- `Condition`
- `#SAFE`
- `#CONTINUE`
- `#ABSTAIN`
- `False Certification Rate`
- `Safe Coverage`
- `Abstention Rate`
- `Mean Repair Gain`
- `Mean Cost`

优先数据源：

- `analysis/research_object_geometry/real_agent_pilot/controller_validation_v1/results/`
- `analysis/research_object_geometry/real_agent_pilot/external_validation_v2/results/`
- `analysis/research_object_geometry/real_agent_pilot/method_validation_v1/results/`

验证要点：

- 不能只报 `false_certification_rate = 0`。
- 必须同时显示 `SAFE` 的出现次数和 `ABSTAIN` 的比例。
- `urllib3` 的 route-partitioned 结果要保留为 boundary case。

### P1. source-only vs source-route 消融

目的：验证 `source-only` 无法暴露 route-level certificate mismatch。

已有现成证据：

- `method_validation_v1` 里 `source_only` 下不同 challenger 基本退化。
- `source_route` 下 `residual_potential` / `high_potential` / `random` 才拉开差异。

建议输出：

- 一张总表：`source_only` vs `source_route` vs `source_route_action`
- 一张机制结论图：`source-only` 无法区分 route mismatch，`source-route` 才能暴露局部证据失配

论文落点：

- `RQ2: Source-route is necessary beyond source-only`

### P2. threshold / budget sensitivity

目的：消除“调参调出来的”质疑。

扫描维度：

- `τs`: `0.50 / 0.60 / 0.70 / 0.75 / 0.80 / 0.90`
- `τg`: `0.50 / 0.60 / 0.70 / 0.80 / 0.90`
- `repair budget`: `1 / 2 / 4 / 6 / 8`

输出：

- `False Certification Rate`
- `Safe Coverage`
- `Abstention Rate`
- `Continue Rate`
- `Cost`
- `risk-coverage curve`

要求：

- 曲线要显示保守性和覆盖率的权衡。
- 不能只报最优点。

### P3. requests / urllib3 oracle appendix

目的：把 pattern-defined oracle 说清楚，降低“正则命中堆出来的”怀疑。

必须补的信息：

- snapshot 版本
- oracle item 粒度
- pattern 规则
- 去重逻辑
- 每个 route 的 oracle 数量

建议补一个小抽样说明：

- 每个 repo 抽样 50 个 oracle positive
- 每个 repo 抽样 50 个 non-oracle candidate
- 报告 sample precision

重点文件：

- `analysis/research_object_geometry/real_agent_pilot/external_validation_requests/reports/EXTERNAL_REQUESTS_VALIDATION_REPORT.md`
- `analysis/research_object_geometry/real_agent_pilot/external_validation_v2/reports/ORACLE_CONSTRUCTION.md`

### P4. 小规模真实 LLM-agent validation

目的：把“dynamic agent workflow”落到真实 stop proposal 和 evidence log。

建议规模：

- `2 repos × 3 seeds × 3 conditions`

条件：

- `single-agent no-new stop`
- `homogeneous multi-agent stop`
- `route-partitioned multi-agent + controller`

记录字段：

- 固定 prompt
- 独立上下文
- 固定预算
- stop proposal
- evidence log
- controller decision

验证目标：

- 证明真实 agent workflow 里也会出现 localized evidence false stop。
- 这只是小规模 validation，不是大 benchmark。


## Baselines

最少补这些对照，不要再扩展复杂方法名：

```text
B0: naive no-new stop
B1: homogeneous multi-agent stop
B2: prompt-diverse multi-agent
B3: source-only geometry controller
B4: source-route geometry controller
B5: Chao / unseen-mass stopping
B6: fixed-budget audit
B7: random repair
B8: high-potential repair
M: evidence-condition controller + residual-potential repair
```

其中最关键的是：

- `source-only` vs `source-route`
- `Chao-only` vs `evidence-condition controller`
- `random/high-potential` vs `residual-potential`

## Metrics

主表建议统一这些指标：

- `False Certification Rate`
- `Safe Coverage`
- `Abstention Rate`
- `Continue Rate`
- `Mean Repair Gain`
- `Mean Cost`
- `mean ± 95% bootstrap CI`
- `paired permutation test`
- `effect size`

## 论文措辞边界

必须保留的稳妥说法：

> diagnostic and control principle, not a universal completion guarantee.

不要写成：

- `residual-potential` 是最优主动搜索
- controller 保证所有工作流完成
- zero false-certification 代表完全充分

## 预期交付

完成后，论文实验部分应当能清楚回答：

1. 为什么 localized evidence 不能直接当 global stop。
2. 为什么 source-route 比 source-only 更关键。
3. 为什么 controller 不是永远保守。
4. 为什么 residual-potential 只是 repair probe，不是最优搜索。
5. 为什么外部 oracle 和真实 agent workflow 都支持同一条证书失配主线。
