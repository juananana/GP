# External Requests Validation Conclusion

## Task

This validation uses a real local snapshot of the open-source `requests` package from the Python environment.

Bounded files:

- `adapters.py`
- `api.py`
- `auth.py`
- `models.py`
- `sessions.py`
- `utils.py`

Oracle is generated by fixed route patterns and used only after blind trajectories are fixed.

## Diagnostic Result

The exposure-localization diagnostic replicates strongly:

| condition | exposure_gini | source_route_coverage_ratio | recall | false_stop_at_90 |
|---|---:|---:|---:|---|
| homogeneous | 0.8885 | 0.25 | 0.1040 | true |
| route_partitioned | 0.6074 | 1.00 | 1.0000 | false |

Interpretation:

```text
homogeneous route reuse creates severe source-route exposure localization and false stopping;
route-partitioned search lowers localization and recovers the full fixed-pattern oracle.
```

This supports the frozen failure law on a real external codebase snapshot.

## Challenger Result

At source-route granularity:

| challenger | mean new true items | cumulative recall |
|---|---:|---:|
| random | 45.535 | 0.2568 |
| low-exposure | 106.000 | 0.4597 |
| low-discovery | 106.000 | 0.4597 |

| high-potential | 177.000 | 0.6980 |
| residual-potential | 177.000 | 0.6980 |

Residual-potential beats random, low-exposure, low-discovery, and free-search continuation.

However, it ties high-potential-only.

## Ablation Interpretation

For this external task, the gain is mostly explained by potential.

The under-exposure term does not add measurable benefit beyond high-potential-only at source-route granularity.

So the external task supports:

```text
runtime-computable potential is useful;
source-route exposure localization is diagnostic;
```

but weakens:

```text
under-exposure x potential is consistently better than potential alone.
```

## Source-Only Boundary

Source-only does not support the residual-potential intervention:

| challenger | mean new true items |
|---|---:|
| high-potential | 257.000 |
| residual-potential | 158.000 |
| random | 180.205 |

At source-only granularity, residual-potential is worse than high-potential and worse than random.

This reinforces the boundary:

```text
Do not claim the method works under coarse source-only coverage.
```

## Honest Decision

External validation supports the paper's diagnostic core:

```text
source-route exposure localization predicts false stopping risk.
```

External validation partially supports the intervention:

```text
residual-potential is better than random/simple low-exposure at source-route granularity,
but it is not better than high-potential-only on this external repo.
```

Therefore:

- Keep `source-route exposure localization` as the paper core.
- Keep `residual-potential challenger` as a derived intervention candidate.
- Do not claim the product term is universally necessary.
- Add a caveat: in some external code tasks, the potential term may dominate.
